# 감사인 견적 평가 관리자 운영 안내

## 접근과 권한

- 관리자는 기존 Firebase Auth 계정으로 로그인합니다.
- 접근 권한은 기존 `admin: true` custom claim으로만 판단합니다.
- 일반 회원의 프로필 `role`이나 이메일 주소는 관리자 권한 근거로 사용하지 않습니다.
- `AUDIT_EVALUATION_ENABLED=true`와
  `AUDIT_EVALUATION_ADMIN_ENABLED=true`일 때만 `/admin/operations`에
  감사평가 운영 메뉴가 표시됩니다.
- 관리자 API는 화면 표시 여부와 별개로 매 요청마다 `requireAdmin`과
  기능 플래그를 다시 확인합니다.

## 다섯 개 업무 메뉴

### 견적 평가 건

농협명, 사업연도, 고객 확인 여부, 처리 상태와 보고서 상태로 평가 건을
찾습니다. 상세 화면에서 업로드 문서의 무결성, 추출 근거, 정정 이력,
점수와 보수 분석, 보고서 버전과 고객 접근 만료일을 함께 확인합니다.

관리자 정정은 변경 사유가 필수입니다. 정정 전 값과 최초 추출값은
덮어쓰지 않고 이력으로 보존되며, 수정자 UID와 수정 시각이 기록됩니다.
확정된 자료를 수정하면 기존 보고서는 유지되고 `보고서 재생성 필요`
상태가 됩니다. 고객의 재확정이 필요한 경우 이를 먼저 안내합니다.

문서 재처리, 보고서 재생성, 고객 링크 재발급은 확인 절차를 거칩니다.
보고서 재생성은 기존 버전을 덮어쓰지 않고 새 버전을 만듭니다.

### 평가기준 관리

- **초안 저장**: 관리자 작업 내용만 보관합니다. 고객 평가에는 사용되지
  않습니다.
- **게시 전 검증**: 총점 100점, 배점과 threshold, 필수 입력값, 적용기간
  충돌을 검사합니다.
- **게시**: 검증된 초안을 이후 생성되는 평가 건에 사용할 수 있게
  합니다.
- **이전 버전 복제/재게시**: 게시본을 직접 수정하지 않고 새 초안 버전을
  만든 뒤 다시 검증하고 게시합니다.

게시된 평가기준과 이미 생성된 보고서의 설정 스냅샷은 변경하지 않습니다.

### 보고서 설정

보고서 제목, 안내·유의 문구, 연락처, 게시된 로고, 승인된 색상,
목차 표시 여부, 워터마크, 안전한 파일명 규칙과 다운로드 기간을
관리합니다. HTML, JavaScript, CSS 또는 임의 실행 규칙은 입력할 수
없습니다. 필수 목차는 숨길 수 없습니다.

보고서 설정도 평가기준과 같은 버전의 초안에 저장됩니다. 초안을 저장한
것만으로 고객 보고서가 바뀌지 않으며, 게시 이후 새로 확정되는 평가 건에
적용됩니다.

### 처리 오류

업로드 실패, 파싱 실패, 문서 불일치, 보고서·PDF 생성 실패, 이메일 링크
발송 실패를 모아서 확인합니다. 각 항목은 고객 영향, 발생 시각,
재시도 횟수와 운영 해결 방법을 표시합니다.

화면에는 안전한 오류 코드와 상관 식별자만 표시합니다. 서버 stack
trace는 Firestore에 저장하거나 고객 응답에 포함하지 않으며, 필요한
기술 조사는 권한이 분리된 런타임 로그에서 수행합니다.

### 감사로그

관리자 정정, 재처리, 보고서 재생성, 링크 재발급, 설정 저장·게시와
보고서 생성·다운로드 기록을 읽기 전용으로 확인합니다. 감사로그의
생성 방식과 저장 키는 관리자 편집 대상이 아닙니다.

## 운영 안전 원칙

1. 고객이 확정한 스냅샷과 과거 보고서를 직접 덮어쓰지 않습니다.
2. 동일 버튼을 반복 실행해도 중복 보고서나 중복 정정이 생기지 않도록
   화면의 진행 상태가 끝날 때까지 기다립니다.
3. 파괴적 작업은 대상 농협명, 문서명 또는 보고서 버전을 확인한 뒤
   실행합니다.
4. 고객 링크를 재발급하면 기존 미사용 링크는 폐기됩니다.
5. 내부 오류 상세에 이메일, 토큰, Storage 서명 URL 같은 민감정보를
   기록하지 않습니다.
