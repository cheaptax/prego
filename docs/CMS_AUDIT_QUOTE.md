# FY27 회계감사 견적 페이지 CMS 운영 안내

기준일: 2026-07-21  
공개 주소: `/events/audit-quote`  
관리자 주소: `/admin/pages/event.auditQuote`

## 편집 범위

관리자는 실제 공개 페이지와 같은 화면을 PC·태블릿·모바일 크기로 미리보며 다음 항목을 편집한다.

- 첫 화면 배지, 큰 제목, 강조 문구와 설명
- 신청 영역 제목·안내, 이메일·담당자 이름·휴대폰 번호의 표시 이름, 입력 예시와 도움말
- 개인정보 수집·이용 동의와 이벤트·혜택 수신 동의의 표시 문구
- 신청 버튼, 무료 신청·계약 의무 안내
- 접수 종료, 입력 검증, 처리 중, 성공, 오류와 재신청 안내
- 제공 혜택 카드, 진행 순서, FAQ의 내용·순서·노출
- 운영 주체와 면책문구
- SEO 제목·설명·검색 노출
- 승인된 글자·색상·반응형 크기·여백·배경·테두리·모서리·그림자
- 신청 카드, 혜택·단계·FAQ 카드와 신청 버튼의 승인된 디자인

CMS 게시본이 없거나 검증에 실패하면 2026-07-20 운영 화면과 동일한 코드 기본값을 사용한다. 공개 화면은 `cmsPublishedPages/event.auditQuote`만 읽고 초안을 읽지 않는다.

## 법적 필수 안내

`견적 신청 영역`과 `운영 주체와 면책문구`는 필수 영역이다.

- 관리 화면에서 숨김을 선택할 수 없고 영역 자체를 삭제할 수 없다.
- 직접 API 요청으로 숨김·잠금 해제·삭제를 시도해도 초안 저장 또는 게시 검증에서 거부한다.
- 개인정보 필수 동의 문구, 무료 신청·계약 의무 안내, 운영 주체와 면책문구는 비워 둘 수 없다.
- 문구 변경은 허용하지만 편집 화면과 게시 전 검사에 경고가 표시된다.
- 해당 문구가 기본값과 다른 게시본은 `수정·게시 이력`에 `필수 동의·면책문구 수정 이력`으로 표시된다.
- 이전 게시본 복원은 공개 화면을 즉시 바꾸지 않는다. 새 초안으로 복원한 뒤 검토하고 다시 게시해야 한다.

개인정보 동의의 필수 여부는 문구와 분리되어 코드와 서버에서 항상 `true`로 검증된다.

## 코드에서 보호되는 값

관리자 편집 데이터는 다음 값에 접근하거나 영향을 줄 수 없다.

- 폼 내부 이름 `email`, `name`, `phone`
- 제출 주소 `POST /api/audit-quote/requests`
- 제출 JSON의 키와 `source` 구조
- `auditQuoteRequests`와 보조 collection 및 Firestore field 이름
- 개인정보 처리 기준 버전, campaign, channel과 page path
- `companyWebsite` honeypot
- Idempotency-Key, origin/body 크기 검사, captcha/App Check 경계
- HMAC 이메일 해시, 중복 방지와 IP·이메일 rate limit
- 견적 요청 생성 transaction, 접수번호와 알림 생성

클라이언트 payload는 CMS 타입을 인자로 받지 않는 `buildAuditQuoteRequestPayload`에서만 구성한다. 표시 문구와 디자인을 바꾸어도 payload가 달라지지 않는다.

## 운영 순서

1. `/admin`의 `페이지 관리`에서 `FY27 회계감사 견적 요청`을 연다.
2. 왼쪽 목록 또는 가운데 실제 화면에서 편집할 영역을 선택한다.
3. 문구·카드·FAQ·단계와 디자인을 바꾸고 PC·태블릿·모바일을 확인한다.
4. 상단의 `초안 저장됨`을 확인한다. 이 상태에서는 공개 페이지가 바뀌지 않는다.
5. `비교`와 게시 전 오류·법적 문구 경고를 확인한다.
6. `게시` 후 `/events/audit-quote`에서 공개본을 확인한다.
7. 되돌릴 때는 `이력`에서 버전을 새 초안으로 복원하고 다시 게시한다.

접수 가능 여부, 종료 시각과 개인정보 처리 기준 버전은 보안·운영 환경 설정으로 유지된다. CMS는 해당 상태에서 고객에게 보여 줄 문구만 관리한다.

## 검증 계약

- 코드 기본값의 데스크톱·모바일 스크린샷은 CMS 연결 전과 픽셀 해시가 동일해야 한다.
- CMS 변경 전후 request payload의 키·값은 동일해야 한다.
- 정상 요청은 기존과 같은 `auditQuoteRequests` 필드로 저장되어야 한다.
- 초안 저장 후 공개 loader 결과는 바뀌지 않고 게시 후에만 바뀌어야 한다.
- 게시 이력 생성, 이전 버전 초안 복원과 롤백 재게시를 통과해야 한다.
- 모바일에서 입력, 필수 동의, 검증 오류, 처리 중, 성공과 서버 오류 상태를 확인한다.
- 운영 사이트에는 검증용 견적 요청을 제출하지 않는다.
